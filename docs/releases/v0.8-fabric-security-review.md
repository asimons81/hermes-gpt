## 1. Verdict

**PASS WITH NORMATIVE HARDENING.**

The G2 architecture survives adversarial review only with the additional G3 controls in this document treated as mandatory implementation constraints. These controls narrow the design. They do not widen authority.

G4 must not weaken, omit, or silently reinterpret them. Any implementation that cannot satisfy one of these controls must fail closed or defer the affected feature.

## 2. Security invariants under attack

G3 attempted to falsify these claims:

1. Fabric callers cannot choose arbitrary destinations or credentials.
2. Remote peers cannot widen coordinator or local authority.
3. Generic A2A agent handling cannot masquerade as verified Fabric acceptance.
4. Transport success or worker prose cannot certify Work Contract completion.
5. Timeout, restart, cancellation, or task-store loss cannot create duplicate write attempts.
6. Time cannot release uncertain write ownership.
7. Stale capabilities and soft ranking cannot override hard safety policy.
8. Caller-controlled remote paths and arbitrary artifact URLs are rejected.
9. Artifact bytes cannot become evidence until full admission succeeds.
10. Evidence from the wrong peer, attempt, contract, authority, or protocol lineage is rejected.
11. Protocol incompatibility cannot silently downgrade verified work to generic A2A.
12. Flight Deck cannot create a new authority path.
13. Fabric makes no cryptographic remote-attestation claim about a fully compromised peer.

All thirteen remain defensible after the hardenings below.

## 3. Mandatory G3 hardenings

### G3-S01: Verified Fabric requires a cryptographically distinct coordinator principal

A managed Fabric peer must authenticate the initiating coordinator as a configured principal before any Fabric operation that can influence execution, evidence, artifacts, cancellation, or reconciliation.

For verified Fabric:

- shared-token identity with IP-derived fallback is not sufficient;
- anonymous/localhost-trust fallback is not sufficient for cross-machine execution;
- a credential shared by unrelated callers is not sufficient;
- the resolved coordinator principal is server-configured and cannot be supplied inside the Fabric payload;
- peer policy binds that principal to allowed Fabric operations, profiles, authorization ceilings, and managed workspaces;
- `coordinator_principal_id` or a safe stable digest is bound into peer attempt state, evidence lineage, write ownership, and audit events.

If the peer cannot resolve a unique allowed coordinator principal, verified Fabric fails closed as `FABRIC_COORDINATOR_IDENTITY_UNVERIFIED`.

### G3-S02: Cross-machine verified Fabric requires authenticated encrypted transport

Bearer authentication over cleartext remote HTTP is not an acceptable Fabric security boundary.

For a non-loopback managed peer, verified Fabric requires one of:

- HTTPS with certificate validation under coordinator policy; or
- an explicitly configured authenticated encrypted tunnel/overlay whose peer identity is verified before A2A traffic is trusted.

Rules:

- remote cleartext `http://` is ineligible for verified Fabric;
- certificate verification cannot be disabled by a Work Contract, router option, or peer advertisement;
- Fabric SHA-256 digests provide lineage/idempotency only and are not substitutes for channel authentication/integrity;
- redirect/destination changes outside the enrolled peer binding are rejected.

Failure is `FABRIC_TRANSPORT_INSECURE` or `FABRIC_PEER_IDENTITY_UNVERIFIED`.

### G3-S03: Write ownership uses a conflict domain, not hash equality of arbitrary path scopes

G2's `write_scope_sha256` is insufficient by itself as the uniqueness key because two different canonical scopes may overlap while producing different digests.

For v0.8, write ownership is intentionally conservative:

- every write-capable attempt acquires one server-defined `write_conflict_domain`;
- the default conflict domain is the entire logical workspace identity;
- the coordinator permits only one ACTIVE Fabric write claim per conflict domain;
- the managed peer independently permits only one ACTIVE local write claim per mapped conflict domain;
- `write_scope_sha256` remains bound for audit and authority validation, but it is not the sole concurrency key;
- finer-grained concurrent write domains are deferred unless a future design proves a deterministic non-overlap relation.

A second attempt whose domain conflicts with an ACTIVE or ambiguous claim fails to `BLOCKED_WRITE_OWNERSHIP`.

### G3-S04: Terminal proof is process-tree/container-unit proof, not parent-PID proof

A write claim cannot be released merely because the originally spawned parent process exited. Descendants may still mutate.

Every write-capable Fabric runner must provide a lifecycle containment primitive that lets the peer prove the execution unit has no live mutable descendants. Acceptable examples include an OS process group/session plus verified descendant handling, a cgroup/systemd scope, a Windows Job Object, or backend-equivalent containment with the same property.

Rules:

- the containment-unit identity is persisted in peer attempt state before/at runner start;
- cancel targets the execution unit, not only the parent PID;
- terminal reconciliation verifies the execution unit is quiescent;
- a backend that cannot provide reliable containment is ineligible for write-capable Fabric execution;
- uncertainty leaves the write claim ACTIVE and state ambiguous/blocked.

This is required for release after success, failure, cancellation, peer restart, and coordinator restart.

### G3-S05: Artifact transfer reads an immutable finalized snapshot

Producer-side path checks followed by later path reopen create a symlink/replacement TOCTOU window.

Before a remote artifact becomes transferable, the peer must finalize it into an immutable attempt-bound snapshot or equivalent stable opened object whose identity cannot be redirected to another path between validation and chunk reads.

Required sequence:

1. resolve the source under the approved mapped workspace;
2. reject denied secret paths, symlinks, special files, and policy violations;
3. freeze/copy/open the exact regular-file object under safe no-follow semantics;
4. compute size and SHA-256 from the frozen object;
5. persist the finalized artifact identity and manifest;
6. serve all `artifact_chunk` reads from that same frozen object, never by re-resolving an attacker-changeable path.

Incomplete or changing snapshots fail admission. Artifact bytes are never executable authority.

### G3-S06: Local policy is revalidated immediately before runner start

Acceptance is not a durable permission grant if local policy narrows before execution actually begins.

Immediately before starting a runner, the managed peer must transactionally re-check at least:

- node enabled state;
- authenticated coordinator principal authorization;
- allowed profile and maximum authorization;
- public/high-impact posture;
- logical workspace mapping revision;
- runner/provider/model allowlists;
- required confinement posture;
- active write-conflict-domain ownership.

Policy may narrow after `accept`; narrowing wins. A queued/accepted attempt whose policy is no longer valid does not start.

If policy changes while a write-capable attempt is already running, the peer records drift and requests/attempts cancellation according to policy, but the write claim remains ACTIVE until G3-S04 terminal proof is established.

### G3-S07: Security-critical schemas are closed by default

Unknown security-affecting fields create parser differential and downgrade risk.

For Fabric v1 security objects:

- unknown top-level fields are rejected unless the schema explicitly permits them;
- extensibility is confined to an explicit bounded `extensions` object whose contents cannot affect authority, destination, workspace, identity, version, write ownership, runner policy, evidence provenance, or artifact source;
- duplicate JSON object keys are rejected before semantic use;
- non-finite numbers are rejected;
- IDs, reason codes, schema names, feature tokens, and bounded strings have explicit length/character constraints;
- canonical digests are computed only after successful schema normalization;
- digest equality is never used as authentication.

Parser disagreement fails closed as `FABRIC_SCHEMA_INVALID` or `FABRIC_IDEMPOTENCY_CONFLICT`.

### G3-S08: Evidence checks declare allowed provenance classes

The coordinator validator must not treat all admitted evidence classes as interchangeable.

Each Fabric-capable Work Contract check must declare which provenance classes may satisfy it. Worker statement/handoff data can never satisfy a check. Managed-peer structured observations may satisfy only checks whose contract/check definition explicitly permits that provenance. Coordinator-verified artifacts and coordinator-local observations remain distinct stronger classes.

Unknown or insufficient provenance leaves the check unsatisfied/inconclusive.

### G3-S09: Remote artifacts are untrusted active content in operator UI

Flight Deck or other trusted-origin UI must not inline-render remote HTML, SVG, JavaScript, or equivalent active content in a way that gains Hermes GPT UI origin authority.

Active formats are download/opaque-resource only unless rendered inside an explicitly isolated sandbox with no privileged bridge, credentials, or same-origin access.

### G3-S10: Audit/event fields are structured and injection-safe

Peer-controlled strings cannot become raw trusted log lines.

Fabric events use validated identifiers, bounded structured fields, fixed reason codes where possible, control-character normalization/rejection, and output escaping appropriate to the renderer. Dispatch/attempt/coordinator/peer identities remain separate fields instead of being concatenated into an ambiguous message string.

## 6. New G3 risks discovered

### F-R031 CRITICAL: coordinator identity confusion through shared credential/IP fallback

**Exploit:** an unrelated caller possessing a shared inbound A2A token, or a caller collapsed to an IP-derived identity, presents a valid-looking Fabric DataPart and reaches the deterministic acceptor as if it were the trusted coordinator.

**Mitigation:** G3-S01.

**Required tests:** shared-token rejection for verified Fabric; wrong coordinator principal; correct principal with disallowed profile; principal rotation/revocation; audit binding.

**Fail closed:** `FABRIC_COORDINATOR_IDENTITY_UNVERIFIED` / `FABRIC_AUTHORITY_DENIED`.

### F-R032 CRITICAL: cleartext remote A2A leaks bearer credential or permits envelope tampering

**Exploit:** remote `http://` transport exposes token and authority-bearing request to the network path.

**Mitigation:** G3-S02.

**Required tests:** remote HTTP ineligible; invalid/expired certificate; hostname mismatch; tunnel identity mismatch; no caller override.

**Fail closed:** `FABRIC_TRANSPORT_INSECURE`.

### F-R033 CRITICAL: overlapping writable scopes bypass hash-keyed write claim

**Exploit:** `/workspace/src` and `/workspace/src/file.py` canonicalize to different hashes but overlap, allowing two ACTIVE writers if hash equality is the lock relation.

**Mitigation:** G3-S03 coarse server-defined conflict domains for v0.8.

**Required tests:** parent/child path scopes; two sibling scopes under workspace; same workspace on different nodes; retry with same domain; read-only attempt does not claim writer slot.

**Fail closed:** `BLOCKED_WRITE_OWNERSHIP`.

### F-R034 CRITICAL: parent process exits while descendant continues mutating

**Exploit:** runner spawns a detached child, parent exits, Fabric releases write claim and starts a retry while descendant still writes.

**Mitigation:** G3-S04.

**Required tests:** detached descendant, cancel race, peer restart with live descendant, parent crash, containment unavailable.

**Fail closed:** backend ineligible or `LOST_AMBIGUOUS` / `BLOCKED_WRITE_OWNERSHIP`.

### F-R035 HIGH: artifact path TOCTOU leaks a different file after validation

**Exploit:** approved path is validated, then replaced or redirected before chunk retrieval.

**Mitigation:** G3-S05 immutable finalized artifact snapshot.

**Required tests:** replace-after-manifest, symlink swap, truncate/grow during finalize, source deletion, chunk replay/reorder.

**Fail closed:** artifact transfer rejected/discarded.

### F-R036 HIGH: authority or workspace policy narrows after accept but before runner start

**Exploit:** attempt is accepted, then node/profile/workspace/runner policy is revoked, but queued work starts under stale acceptance.

**Mitigation:** G3-S06 immediate pre-start revalidation.

**Required tests:** disable node after accept; lower authorization ceiling; remove workspace mapping; remove runner/model allowlist; confinement becomes unavailable.

**Fail closed:** attempt does not start; blocked/denied with audit event.

### F-R037 HIGH: parser differential/unknown field creates security semantic disagreement

**Exploit:** coordinator ignores an unknown/duplicate field while peer interprets it as authority, destination, workspace, or execution policy.

**Mitigation:** G3-S07 closed schemas and explicit extensions namespace.

**Required tests:** duplicate keys, unknown top-level fields, non-finite numbers, overlong IDs, Unicode/control-character edge cases, unknown required extension semantics.

**Fail closed:** `FABRIC_SCHEMA_INVALID`.

### F-R038 HIGH: admitted evidence provenance is too weak for the requested check

**Exploit:** a managed peer observation is admitted structurally and then treated as equivalent to coordinator-observed or artifact-verified evidence for a check that requires stronger proof.

**Mitigation:** G3-S08 check-specific provenance policy.

**Required tests:** worker statement presented as proof; peer observation for coordinator-only check; artifact-required check without admitted artifact; unknown provenance class.

**Fail closed:** check remains unsatisfied/inconclusive.

### F-R039 HIGH: remote active artifact compromises trusted operator UI

**Exploit:** malicious HTML/SVG/JS artifact is rendered same-origin inside Flight Deck and reaches privileged UI/session surfaces.

**Mitigation:** G3-S09.

**Required tests:** HTML/SVG/script payloads, MIME spoofing, extension mismatch, sandbox escape assumptions, download-vs-preview policy.

**Fail closed:** opaque/download-only or isolated sandbox rendering.

### F-R040 MEDIUM: peer-controlled audit strings spoof incident lineage

**Exploit:** control characters/newlines/HTML-like content make one peer event appear to be another event/identity in logs or UI.

**Mitigation:** G3-S10.

**Required tests:** newline/control characters, terminal escapes, HTML metacharacters, oversized reason strings, identity lookalikes.

**Fail closed:** field rejection/normalization and unambiguous structured rendering.

## 8. Deferred rather than weakened

The following are explicitly deferred if the implementation cannot safely provide them:

- write-capable execution on a backend lacking process-tree/container-unit terminal proof;
- fine-grained concurrent writers within one logical workspace without a proven conflict relation;
- verified Fabric over cleartext remote A2A;
- verified Fabric from shared-token/IP-fallback coordinator identity;
- same-origin active artifact preview without a hardened sandbox;
- evidence-based completion for checks whose required provenance cannot be established.

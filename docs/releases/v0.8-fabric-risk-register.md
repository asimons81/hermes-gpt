Severity:

- **CRITICAL**: can create unauthorized/high-impact execution, false completion, credential exposure, or silent duplicate writes.
- **HIGH**: can materially violate authority/evidence/recovery guarantees.
- **MEDIUM**: can cause incorrect placement, degraded observability, or bounded operational failure without authority escalation.
- **LOW**: usability/operability issue with a safe failure mode.

G2 acceptance means the architecture contains a concrete mitigation, implementation owner, verification obligation, and fail-closed state. G3 attacked those assumptions and added mandatory hardenings where the G2 design was insufficient.

## 3. Normative G3 security controls

The complete attack reasoning and ADR-by-ADR verdicts are in `docs/releases/v0.8-fabric-security-review.md`. G4 must treat these ten controls as mandatory:

1. **G3-S01 coordinator principal**: verified Fabric requires a unique configured authenticated coordinator principal; shared-token/IP fallback is not enough.
2. **G3-S02 secure transport**: non-loopback verified Fabric requires authenticated encryption with peer verification; remote cleartext HTTP is ineligible.
3. **G3-S03 write conflict domain**: default writer serialization is logical-workspace-wide; path-scope hash equality alone is not a safe conflict relation.
4. **G3-S04 lifecycle containment**: write claim release requires the complete execution unit/process tree to be quiescent, not merely parent PID exit.
5. **G3-S05 immutable artifact snapshot**: manifests and chunks bind to one frozen validated object with no mutable-path reopen.
6. **G3-S06 pre-start policy revalidation**: local authority/workspace/runner/confinement policy is checked again immediately before execution begins.
7. **G3-S07 closed schemas**: reject unknown security fields, duplicate keys, ambiguous numbers/IDs; extensions are explicitly bounded and non-authoritative.
8. **G3-S08 evidence provenance policy**: every check defines which evidence classes may satisfy it; worker statements never do.
9. **G3-S09 untrusted active artifacts**: remote active content cannot inherit trusted Flight Deck origin/bridge authority.
10. **G3-S10 injection-safe audit lineage**: distributed events remain structured, bounded, escaped, and identity-unambiguous.

## 5. G3 deferred-rather-than-weakened list

If an implementation cannot provide the required control, the feature is deferred or the candidate becomes ineligible. Do not weaken the trust boundary to preserve scope.

Deferred/ineligible cases include:

- write-capable backend without execution-unit/process-tree containment;
- fine-grained concurrent write domains inside one logical workspace without a proven non-overlap model;
- remote verified Fabric over cleartext A2A;
- remote verified Fabric with shared-token/IP-fallback coordinator identity;
- same-origin active artifact preview without an isolated sandbox;
- Work Contract completion where the required evidence provenance cannot be established.

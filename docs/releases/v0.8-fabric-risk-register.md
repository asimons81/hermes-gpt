Severity:

- **CRITICAL**: can create unauthorized/high-impact execution, false completion, credential exposure, or silent duplicate writes.
- **HIGH**: can materially violate authority/evidence/recovery guarantees.
- **MEDIUM**: can cause incorrect placement, degraded observability, or bounded operational failure without authority escalation.
- **LOW**: usability/operability issue with a safe failure mode.

G2 acceptance means the architecture now contains a concrete mitigation, implementation owner, verification obligation, and fail-closed state. It does not mean the risk has passed adversarial security review.

## G2 architecture blocker disposition

The architecture blockers identified in the research pass are now mapped to explicit accepted decisions:

1. **F-R004/F-R005/F-R006/F-R016**: non-expiring logical write claims, monotonic epochs, durable coordinator/peer journals, attempt-specific cancel, fail-closed reconciliation.
2. **F-R002/F-R007**: server-controlled ceilings plus deterministic peer acceptor before LLM/runner execution.
3. **F-R003/F-R017**: versioned evidence admission with coordinator-only Work Contract verdict ownership.
4. **F-R012/F-R013/F-R014/F-R015**: logical workspace mapping plus manifest-first, coordinator-pulled A2A chunk transfer and two-sided artifact checks.
5. **F-R008/F-R009/F-R010/F-R011**: live identity, provenance/freshness, authority/capability separation, hard-filter-before-rank.
6. **F-R020**: explicit major/feature negotiation and no verified downgrade to generic A2A.
7. **F-R018**: explicit no-remote-attestation threat boundary.

There are no remaining architecture-undefined CRITICAL/HIGH mitigations. Every CRITICAL/HIGH item remains open to attack in G3.

## G3 attack assertions

G3 #30 must actively try to falsify at least these assertions:

1. no Fabric caller can select an arbitrary destination or credential;
2. no remote peer/worker can widen coordinator or local peer authority;
3. no generic A2A LLM path can masquerade as verified Fabric acceptance;
4. no transport/peer self-report alone can produce Work Contract satisfaction;
5. no timeout/restart/cancel ambiguity can create a second write-capable attempt automatically;
6. no time-based expiry can release uncertain write ownership;
7. no stale capability or soft score can bypass a hard safety requirement;
8. no caller-controlled remote path or arbitrary artifact URL is accepted;
9. no artifact becomes evidence before full size/hash admission;
10. no wrong-lineage evidence is admitted;
11. no protocol failure silently downgrades to generic A2A verified execution;
12. no Flight Deck route creates authority outside server-side Operator gates;
13. no docs/UI/release claim implies cryptographic truth from a fully compromised peer.

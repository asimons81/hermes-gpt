# Hermes GPT v0.8 Fabric Risk Register

- Status: IN PROGRESS, G2
- Program: #27
- Gate: #29
- Security gate: #30
- Research source: `docs/releases/v0.8-fabric-research-package.md`

Severity scale:

- **CRITICAL**: can directly create unauthorized/high-impact execution, false completion, credential exposure, or silent duplicate writes.
- **HIGH**: can materially violate authority/evidence/recovery guarantees.
- **MEDIUM**: can cause incorrect placement, degraded observability, or bounded operational failure without authority escalation.
- **LOW**: usability/operability issue with a safe failure mode.

All mitigations are architecture candidates until G2 acceptance and G3 review.

## Architecture blockers for G2 exit

G2 cannot pass while the architecture leaves these unresolved:

1. F-R004/F-R005/F-R006/F-R016 write-attempt concurrency and restart semantics;
2. F-R002/F-R007 authority enforcement on the managed peer;
3. F-R003/F-R017 evidence ownership and lineage;
4. F-R012/F-R013/F-R014/F-R015 workspace/artifact boundary;
5. F-R008/F-R009/F-R010/F-R011 identity/capability/router boundary;
6. F-R020 protocol compatibility policy;
7. F-R018 honest compromised-peer threat model.

## G3 handoff requirement

Before #30 begins adversarial review, every CRITICAL/HIGH risk must have:

- an accepted architecture mitigation;
- a named implementation slice;
- at least one required regression/integration test;
- an explicit fail-closed state when mitigation cannot establish safety.

## 3. Per-surface detail

### 3.1 Profiles (surface 1)
- Source: `~/.hermes/profiles/<profile>/` and the `hermes profile list` view.
- Verified state: 9 profiles on host. Gateway currently serves all 9 (`gateway_state.json` `served_profiles`); `hermes profile list` shows gateway running only for `default` (PID 1023882), stopped for the rest (per-profile gateway processes start on demand; multiplex_profiles=true).
- Owner: Hermes Agent core, per-profile runtimes.
- Cadence: config static; activity continuous.
- Sample schema (profile dir): config.yaml (model/provider), profile.yaml, SOUL.md, memories/, skills -> shared, auth.json, cron/, state.db, memory_store.db, logs/, home/.
- Sensitivity: HIGH (auth tokens in auth.json, .env; SOUL prompts; memories). All files 0600/0700.
- Read-only: `hermes profile list`; file read with permissions honored. No mutation.

### 3.2 Fleet agents (surface 2)
- Sources: gateway state (S02), A2A registry/tasks (S03), fleet authority manifest (S04), per-profile activity (S11), fleet dispatch audit records (S14).
- Verified: 1 A2A peer registered (`Hermes Arch Lead`, http://192.168.4.41:8765, token-protected, max_concurrent_tasks 1, task_timeout 300s); 7 A2A tasks; gateway serves 9 profiles; fleet dispatch recorded 426 work orders + 191 dispatches in the audit log.
- Sensitivity: HIGH for A2A config (auth_token) and task payloads.
- Read-only: `hermes a2a registry list --json`, `hermes gateway status`, sqlite ro, `hermes_operator_doctor` (checks fleet policy/authority). `hermes fleet status <agent>` performs a live peer health check (read-only HTTP).
- Gap note: fleet authority manifest (S04) is absent on this host — fleet dispatch surfaces should report "authority not configured" instead of failing hard.

### 3.3 Codex jobs (surface 3)
- Two distinct stores:
  - Hermes GPT operator jobs (S05): `<hermes_root>/codex-jobs/<job_id>.json` + `.jsonl` — the canonical store the operator writes; **absent on this Linux host** (no directory). On the Windows host where hermes-gpt serves ChatGPT, this lives at `%LOCALAPPDATA%\hermes\codex-jobs\`.
  - Codex CLI native (S06): `~/.codex/` — `sessions/YYYY/MM/DD/rollout-*.jsonl` (full Codex session transcripts), `.codex-global-state.json`, `agents/`, `auth.json`.
- Verified: 5+ Codex rollout sessions in `~/.codex/sessions/2026/08/` and `2026/07/`; `hermes_codex_status` probes the codex launcher (`.hermes/bin/codex-9r`, WindowsApps shim fix on `fix/codex-windowsapps-wineerror-5`).
- Sensitivity: HIGH (prompts, transcripts, auth).
- Read-only: `hermes_codex_jobs` / `hermes_codex_job_status` / `hermes_codex_job_result` (operator); file read of `~/.codex`; `hermes_codex_status` health probe.
- Gap: see G1 — no operator job store on this host; Mission Control must treat "codex-jobs present" as conditional and fall back to `~/.codex` + audit log.

### 3.4 Cron activity (surface 4)
- Sources: S07 (jobs.json registries), S08 (executions.db), S09 (output/heartbeat/notepad), plus per-profile cron homes.

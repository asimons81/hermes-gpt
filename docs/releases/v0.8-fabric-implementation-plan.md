## 1. Accepted architecture inputs

G4 implementation must conform to:

- `docs/design/v0.8-fabric-architecture.md`;
- `docs/design/v0.8-fabric-adrs.md`;
- `docs/releases/v0.8-fabric-risk-register.md`;
- this plan.

Key accepted decisions:

1. official Hermes A2A v1.0 is transport;
2. verified Fabric execution requires a deterministic managed Hermes GPT peer acceptor;
3. Fabric uses structured A2A DataPart operations, not natural-language authority interpretation;
4. coordinator and peer maintain durable transactional attempt journals;
5. stable `dispatch_id` and per-attempt `attempt_id` are distinct;
6. write-capable work uses non-expiring logical write claims and monotonic epochs;
7. managed-node identity, credentials, profiles, authority ceilings, workspace mappings, and policy remain server-controlled;
8. capability facts have provenance/freshness and never imply authorization;
9. router hard-filters before deterministic `fabric-router-v1` ranking;
10. remote paths are server-resolved from logical workspace IDs;
11. remote evidence is coordinator-admitted observation input, not a verdict;
12. artifacts use manifest-first coordinator-pulled bounded A2A chunks;
13. cancel is attempt-specific and cannot release write ownership by transport state alone;
14. polling plus journals defines correctness;
15. Flight Deck gains bounded read models, not new authority;
16. protocol negotiation is explicit and never silently downgrades to generic A2A verified execution;
17. fully compromised peer truthfulness is outside v0.8 cryptographic guarantees.

## 3. G3 security package / #30

G3 attacks the accepted architecture before production implementation.

### Required attack assertions

Attempt to falsify:

- registry-only destination/credential resolution;
- coordinator and peer authority ceilings;
- deterministic acceptor before generic LLM path;
- remote self-report cannot satisfy a contract;
- idempotent replay and conflicting identity rejection;
- timeout/restart/cancel cannot create a second automatic writer;
- no time-based expiry releases uncertain write claims;
- workspace mapping cannot be caller escaped;
- capability advertisement/soft ranking cannot become authorization;
- stale identity/capability cannot remain eligible;
- protocol mismatch cannot downgrade to generic A2A verified execution;
- wrong-lineage evidence cannot be admitted;
- artifact source/transfer cannot escape paths, leak secrets, cause SSRF, or bypass size/hash checks;
- peer credentials cannot appear in protocol/events/UI;
- Flight Deck cannot bypass server-side Operator mutation gates;
- compromised-peer documentation does not overclaim remote attestation.

### Required G3 output

- finding list with severity;
- affected ADR/risk IDs;
- exploit/precondition;
- required architecture amendment or implementation control;
- regression/adversarial test;
- final statement that no CRITICAL/HIGH trust-boundary finding remains unresolved.

Any architecture-changing G3 finding reopens G2 documents before implementation.

## 6. G4-C / #34: Write ownership, artifacts, cancellation, recovery

### Goal

Make distributed mutation and artifact movement survive transport/process ambiguity without silent duplicate writes or unsafe file transfer.

### Owned ADRs

- ADR-012 through ADR-014;
- ADR-019;
- ADR-021 through ADR-025;
- ADR-031/032.

### Owned risks

- F-R004 through F-R006;
- F-R012 through F-R016;
- F-R021;
- F-R029.

### Required implementation

- coordinator logical write claims;
- peer-local write claims;
- monotonic write epochs;
- compare-and-set state transitions;
- restart reconcile engine;
- attempt-specific cancel/reconcile;
- `hermes.fabric-artifact-manifest/v1`;
- peer attempt artifact registry;
- manifest-first artifact API;
- coordinator-pulled bounded A2A chunk transfer;
- bounded temporary receive and atomic admission;
- recovery/write-ownership reason codes.

### Write safety invariants

- one ACTIVE coordinator claim per logical write scope;
- peer persists local claim before runner mutation;
- no automatic time expiry;
- no new writer while previous write state is ambiguous;
- A2A task disappearance does not release claim;
- cancel request/result alone does not release claim;
- epoch is stale-command/audit fence, not filesystem proof;
- automatic release requires reconciled terminal proof;
- irreconcilable ownership becomes `BLOCKED_WRITE_OWNERSHIP`.

### Artifact invariants

- artifact ID resolves from peer attempt registry only;
- no caller remote path;
- no arbitrary URL fetch;
- regular file only;
- allowed mapped root only;
- denied secret paths blocked;
- symlink/special files blocked;
- size/media/extension policy;
- manifest SHA-256/size;
- coordinator chunk bounds;
- temporary receive;
- exact size/hash before atomic admission;
- rejected/incomplete artifact never becomes evidence.

### Required tests

- timeout while remote write active;
- coordinator restart;
- peer restart;
- lost A2A task;
- missing runner certainty;
- duplicate cancel;
- cancel/completion race;
- cancel/retry race;
- cross-node retry while claim active;
- no time-expiry release;
- stale epoch rejection;
- valid artifact;
- traversal/absolute path;
- symlink escape;
- special file;
- denied secret source;
- oversize;
- URL/SSRF injection;
- chunk reorder/overlap/gap;
- truncation/growth;
- hash mismatch;
- incomplete transfer cleanup;
- irreconcilable write blocks.

### Slice exit

Fabric can lose task/process continuity and still reach an explainable safe state with no silent second writer and with artifact bytes admitted only under verified lineage/bounds.

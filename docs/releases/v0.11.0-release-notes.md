# Hermes GPT v0.11.0 — Gemini Spark custom-app support, profile-aware Bot Chat, MCP SDK 2, security remediation

> **STATUS: CANDIDATE.** Prep record for the v0.11.0 release. Publication gates (tag, GitHub release, PyPI) are tracked on the release workstream; the GitHub release page becomes the published record once shipped.

Hermes GPT v0.11.0 is a compatibility-and-reach release on top of the vNext slice-1 foundation. It adds an opt-in Google Gemini Spark custom-app client profile, MCP Python SDK 2.x support (SDK 1.28.1+ retained), profile-aware Bot Chat and session delivery, and the post-v0.10 security remediation — with no change to the read-only / dry-run / shadow authority ladder and no new mutating surface enabled by default.

## Gemini Spark custom-app support (opt-in client profile)

- Added an opt-in second OAuth client profile for Google's consumer Gemini Apps "Custom apps for Spark" connector.
- Enable with `HERMES_GPT_OAUTH_GEMINI_ENABLE=1` plus `HERMES_GPT_OAUTH_GEMINI_CLIENT_ID` / `HERMES_GPT_OAUTH_GEMINI_CLIENT_SECRET` / `HERMES_GPT_OAUTH_GEMINI_REDIRECT_URI`; incomplete configuration fails startup validation.
- The Gemini client has its own secret, its own exact-match redirect allowlist, and an isolated access-token membership check — the primary ChatGPT client secret and redirects are untouched, and single-client behavior is byte-identical when the profile is disabled.
- Verified end-to-end against the real Google consumer connector: discovery, authorize (302), back-channel token exchange (PKCE S256 + `resource` match), `tools/list`, and a read-only `hermes_skill_list` call — served from a dedicated loopback instance behind an authenticated HTTPS tunnel on a read-only profile.
- Setup guide: `docs/gemini-spark.md`.

## MCP Python SDK 2.x support

- The server now runs on `mcp` 1.28.1+ or 2.x with identical local stdio, HTTP/SSE transport settings, authentication, and Operator gates.
- Codex Operator aliases now declare normalized result signatures, avoiding SDK 2 output-validation failures.
- CI tests both SDK families and minimum versions with wire-level negotiation and result assertions.

## Profile-aware Bot Chat and session delivery

- MCP session history and control are profile-aware: session tools resolve the selected Hermes profile home (validated against the operator policy allowlist), pass profile home + identity to Hermes, and key concurrency by profile + session ID.
- Added canonical Bot Chat delivery: `hermes_bot_chat_get` / `hermes_bot_chat_send` with compression-tip resolution, behind the existing session gates.
- The cross-process token-store lock is portable on Windows (msvcrt one-byte region locking) while retaining flock on POSIX.

## Security and reliability remediation

- Signed OAuth access tokens now require durable-store presence (a valid MAC alone never suffices); revocation retires tokens and advances a durable epoch in one SQLite transaction with permanent retirement tombstones and epoch-bound authorization codes.
- Refresh rotation is atomic with fail-closed corruption handling and flock-serialized revoke/rotate.
- Controller reconcile/trigger persistence is gated behind workspace + direct apply mode; `dry_run=True` is a truthful zero-controller-write preview.
- Mission-ledger pagination advances only over returned events with per-source watermark cursors and bounded hostile-cursor decoding.
- PyYAML promoted to a runtime dependency; plan readiness requires every declared parent to exist and be completed; controller observation binds to the frontier node's contract hash.

## Fleet enrollment

- Added a generic loopback Agent Card (`/.well-known/agent-card.json`, env-driven identity) served behind the existing Bearer/OAuth middleware, with a loopback short-circuit so co-located fleet tools do not deadlock the single event loop.
- Unknown manifest peers are admitted at the lowest profile ceiling (default only) instead of rejecting the whole manifest, so freshly enrolled machines validate without a code change. Profile-ceiling enforcement is unchanged.

## Fixes

- `hermes_operator_doctor` and mission diagnostics now handle a JSON `gateway.pid` (supersedes #62; reuses the shared gateway-PID reader and hardens it against undecodable JSON bytes).

## Compatibility and safety

- Hermes GPT remains local-first and intended for trusted-machine/private-boundary deployment; default behavior is read-only and mutating Operator actions stay opt-in and dry-run-first.
- The connector surface acceptance gate pins the merged v0.11.0 surface at **137 tools** with no duplicate registration and `serverInfo.version == versioning.VERSION` for the checkout.
- A GitHub release and a PyPI release are separate distribution channels; verify the published version on each channel.

## Distribution

- GitHub release `v0.11.0` with wheel + sdist attached.
- PyPI: `hermes-gpt==0.11.0` published by the `Publish to PyPI` tag workflow (trusted publishing).

## Rollback

- Installs: pin back to `hermes-gpt==0.10.0` (PyPI) or check out tag `v0.10.0`.
- Live deployments: restore the previous checkout commit and restart the server unit; the OAuth/token stores are forward-compatible (no destructive migration), and the Gemini client profile is opt-in, so disabling `HERMES_GPT_OAUTH_GEMINI_ENABLE` returns to single-client behavior.

Implementation is decomposed into **independently verifiable slices**. Each
slice satisfies the G3 DoD: schema + validator + tool registration + audit
wiring + tests green in CI + doc update. Slices can land in any order subject
to the dependency edges shown; each is reviewable and mergeable alone.

---

## 1. Guiding rules

1. **CI green before merge** (R1). Slice 0 must land first.
2. **Additive only.** No renames, no removals, no existing-schema migration.
3. **Every new mutation** maps to an existing authority class with an explicit
   gate and audit wiring.
4. **Evidence over assumption.** No slice claims behavior without a passing
   test that proves it (adversarial where safety-relevant).
5. **Docs in the same slice.** README/docs/operator-mode/oauth/retention/
   CHANGELOG updated by the slice that changes behavior.

## 3. Slice specifications

### S0 — Fix CI (hermes_constants import hermeticity)

**Problem.** `operator_skills._call_skill_manager` imports
`hermes_constants.set_hermes_home_override` unconditionally inside
`if profile_home is not None:`. On CI (no Hermes Agent source root on
`sys.path`) the import raises, failing 8 tests. Verified locally:
`env -u PYTHONPATH .venv/bin/python -m pytest test_operator_skills.py -q`.

**Design.** Wrap the `hermes_constants` import in try/except (the module
already uses this optional-import pattern for vision/web/skill manager); on
unavailable, degrade to the existing "skill manager unavailable" error path
instead of raising. Keep the behavior identical when the import succeeds.

**DoD.**

- `python -m pytest` green on all three CI Pythons (3.10–3.12).
- Existing skill-manager behavior unchanged when Hermes root is present.
- No safety test weakened or skipped.

### S1 — MCP compatibility manifest + tests

**Design.** Pin and verify the protocol surface per research §3.1.

- New `docs/mcp-compatibility.md`: minimum supported MCP protocol revision
  (**2024-11-05**), supported revisions from the installed SDK (1.28.x:
  through **2025-11-25**), transport matrix (stdio, streamable HTTP, SSE),
  ChatGPT + Codex client notes, OAuth metadata advertisement.
- New `test_mcp_compat.py`: asserts the running SDK's
  `SUPPORTED_PROTOCOL_VERSIONS` include ≥ 2024-11-05 and 2025-11-25 when
  available; asserts server `initialize` negotiation and HTTP tool metadata
  security schemes (`oauth2`/bearer/noauth).
- `pyproject.toml`: keep `mcp[cli]>=1.0,<2` (SDK 1.x floor enforced by
  maintainer skill) — do **not** hard-pin 1.28 in metadata; the manifest
  documents the verified floor.

**DoD.** Manifest doc current; compat tests green; README references the
manifest.

### S2 — Long-running lifecycle: restart reconciliation + idempotent advance

**Design.** Per ADR-007.

- New `operator_recovery.py`: startup hook + `hermes_operator_recover`
  extension (dry-run-first, apply gate) that:
  - lists swarm workflows, finds stages in `running`, marks them `blocked`
    with `reason: interrupted_by_restart` (never auto-advances);
  - reloads durable token envelope (when S5 landed) and verifies integrity;
  - returns a bounded reconciliation summary.
- `operator_swarm.py`: `hermes_swarm_stage_advance` becomes idempotent for
  already-validated stages; add `interrupted_by_restart` reason to blocked
  stage records; lifecycle states documented in `docs/operator-mode.md`.

**DoD.** Kill/restart integration test: stage in `running` → after restart →
`blocked` with reason; manual advance resumes; re-advance of a validated stage
is a no-op. No auto-execution path exists.

### S3 — Review-accept writer

**Design.** Per ADR-003.

- New `operator_review.py`: `hermes_review_accept(contract_sha256, task_id,
  reviewer, verdict, evidence_refs, approval_reference, dry_run, confirm)`.
  Owner-level gate; distinct-reviewer check at write time; writes
  ReviewAcceptanceRecord to `<hermes_data>/review-evidence/review-acceptances.jsonl`
  (atomic); audits every call.
- `operator_contract.py`: `_check_review` gains the new store as an evidence
  source (contract_sha256 match, reviewer != assignee), keeping the existing
  two paths.

**DoD.** Adversarial tests: self-review rejected at write + validate; distinct
reviewer enforced; verdict vocabulary bounded; `NOT_SATISFIED` without
evidence; `SATISFIED` with valid record; audit record present for every accept.

### S4 — Structured event history surface

**Design.** Per ADR-004/ADR-005.

- New `operator_events.py`: read-model normalizer over operator audit JSONL,
  swarm-workflows JSON, codex-jobs JSON, cron executions.db (SQLite ro),
  kanban task_events (SQLite ro). EventRecord view schema (§6.3 of
  architecture). Redaction invariants from Mission Control; per-source
  allowlist `HERMES_GPT_EVENTS_ALLOWED_SOURCES` (unset=all/list=only/empty=none);
  retention window `HERMES_GPT_EVENTS_MAX_AGE_DAYS` (default 90);
  bounded caps + TTL cache.
- Tools `hermes_events_query` / `hermes_events_tail` registered in `server.py`
  under `read_only`; every call audited.

**DoD.** No-raw-body property tests across all five sources; allowlist
semantics tests; retention filter; truncation/caps; query by subject_id returns
ordered timeline for a known workflow/task; all read-only (no store writes).

### S5 — Durable encrypted token storage + OAuth promotion

**Design.** Per ADR-001; **requires legal sign-off (R4)**.

- New `token_store.py`: encrypted envelope (§6.4), AES-256-GCM, key management
  (keyring → key file → env), rotation (`kid`), revocation API.
- `oauth_auth.py`: persist/reload tokens through `token_store`; no token
  material in audit or MCP responses.
- Tools `hermes_oauth_status` (read_only) and `hermes_oauth_revoke`
  (owner + confirm, pending legal scope decision).
- Promote OAuth from CHANGELOG "Unreleased" to a shipped, documented feature in
  `docs/oauth.md`; add `cryptography` (+ optional `keyring`) to dependencies;
  extend `test_package_hygiene.py`.

**DoD.** Ciphertext-on-disk test (no plaintext); restart reload test; rotation
and revoke tests; oauth test suite green; `hermes_oauth_status` shows
presence/expiry only; legal sign-off recorded before merge.

### S6 — Authority explainability

**Design.** Document the authority mapping for every new surface (S3/S4/S5/S2)
in `docs/operator-mode.md` and a v0.7 surface manifest (mirroring the v0.6
surface manifest pattern): tool name, authority class, gates, audit, allowlist.
Each new tool's docstring carries its authority class.

**DoD.** Manifest reviewed; per-tool authority tests: denied below the
required level, allowed at/above, dry-run-first enforced, audit written.

### S7 — Flight Deck UI presentation contract (D2-A)

**Design.** Consume the architecture §9.2 contract and the media lane's
interaction design (t_dd366ab6). Deliver:

- The presentation contract as a doc (`docs/design/v0.7-flight-deck-ui-contract.md`),
  describing the view-model sources a Flight Deck UI may render.
- A thin read-only consumer test proving a dashboard-like consumer can render
  the surfaces without mutation (optional; only if media/Tony approve a
  dashboard scope).

**DoD.** No new authority; UI actions map to existing `hermes_*` tools; media
conflicts flagged and resolved.

### S8 — Cross-machine seams (stretch)

**Design.** Per ADR-008.

- New `seams.py`: `DispatchAdapter` and `EvidenceProvider` Protocols.
- `test_seams.py`: two-process-one-host fake — process A implements
  `DispatchAdapter`, process B implements `EvidenceProvider`, exercised over
  loopback; proves the interface contract without remote execution.

**DoD.** Interface tests pass; no remote implementation exists; docs mark this
as stretch with no remote behavior promised.

### S9 — Release hygiene

**Design.** Version bump to 0.7.0 in `pyproject.toml`; CHANGELOG entries;
`README.md` + `docs/README.md` updates; release notes; package data includes
new docs; `RELEASE_CHECKLIST.md` run (release doctor PASS or WARN-only,
package hygiene, private-file scan, retention); GitHub + PyPI published as
separate explicit actions per G5.

## 4. Verification and acceptance

- **Staging environment:** each slice merges to master only when CI is green;
  no staging server required beyond the existing test suite.
- **Independent verification (G4):** default + legal verify the review-evidence
  writer adversarially, event surface no-raw-body, OAuth against a live
  ChatGPT connector, and the security/redaction test suite; legal signs off on
  token storage + retention.
- **Evidence attached:** each slice attaches its test report and changed-file
  list to the implementation card (t_d31703e4).

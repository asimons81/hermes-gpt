## D5 — ADR-007 "startup hook" not implemented; recovery is tool-only (P2, spec-vs-implementation)

- Files: `docs/design/v0.7-flight-deck-adrs.md` ADR-007 (says
  `operator_recovery.py` "runs on startup"), implementation
  `operator_recovery.py` + `server.py`
- Actual: reconciliation is exposed only as the `hermes_operator_recover` /
  `hermes_swarm_reconcile` tool. There is **no startup hook** in
  `server.py` (no call to reconcile in `build_server`, `_run_legacy_server`,
  or the uvicorn path). After a restart, interrupted stages stay `running`
  until an operator explicitly invokes reconcile with `apply=true`.
- Impact: the fail-closed property is intact (never auto-advances, dry-run
  first) — this is **not** a safety regression. But "restart-safe continuity"
  is operator-driven, and ADR-007's automatic-hook design intent is
  unimplemented. Docs (operator-mode.md, release notes) correctly describe the
  tool surface, so user-facing docs are not wrong; only ADR-007 overclaims.
- Options for follow-up: (a) accept tool-driven recovery and amend ADR-007
  docs; (b) implement a dry-run-only startup hook (reconcile reports but never
  mutates without operator apply), which preserves fail-closed.

## D6 — Operative token key source on this host is the key-file fallback (P2, operational posture / legal gate)

- Verified live: `token_store.save_tokens` resolved `kid: keyfile`,
  `source: keyfile` on this host (no keyring service available on the GEEKOM
  Arch host). This is the documented "materially weaker" path (legal memo S1;
  ADR-001): key file sits in the same `secrets/` dir as the ciphertext (both
  0600).
- Impact: not a code defect — it is exactly the designed and disclosed
  fallback. But it is the **operative** posture on the primary host, so the
  pending legal sign-off on key-file fallback (R4/R9/S1) is a genuine
  release gate, not a formality. Consider keyring installation or documenting
  the env-key alternative for this host before shipping.
- Suggested fix: none in code; record legal sign-off; optionally install a
  keyring backend (`python-keyring` + `secretstorage` / kwallet) on the host.

This document is the historical release-prep record; the GitHub release page is the published record.

Hermes GPT v0.10.0 is the vNext slice-1 release: it adds the deterministic MissionPlan decomposition DAG, read-only derived capability-manifest and mission-ledger views, a dry-run mission budget envelope, dry-run placement scoring, semantic failure classification with a deterministic smallest-first recovery matrix, and a supervised mission controller running in shadow/observe mode. The slice is strictly additive and decision-only: every new surface preserves the existing read-only / dry-run / shadow authority ladder, and none of the ~27 new tools can mutate a Mission, dispatch work, or approve anything in this release.

## MissionPlan (decomposition DAG)

- Added `hermes_plan_create/get/list/validate/decompose/review/node_transition/set_status`.
- Plans are deterministic, bounded decomposition DAGs over a `MissionSpec`; `hermes_plan_validate` is a pure read-only validator and `hermes_plan_decompose` produces a bounded DAG.
- `create`, `node_transition`, and `set_status` mutate only the isolated plan store (dry-run-first, `confirm` + `dry_run` defaults) and are read-only with respect to the Mission lifecycle; `get/list/review` are read-only.
- Node advance goes through a validated state machine; set-status is operator-reviewable.

## Derived capability-manifest and mission-ledger views (read-only)

- Added `hermes_capability_manifest`, `hermes_mission_ledger`, and `hermes_mission_ledger_replay`.
- The manifest folds the Fabric node registry, Fleet authority manifest, profile toolsets/skills, and provider manifests into one queryable capability index, with `include_cache` and optional `source`/allowlist filtering and bounded `limit`.
- The ledger is a merged, replayable, cursor-paginated per-mission event timeline; `hermes_mission_ledger_replay` replays a mission's full history.
- All three register with explicit `readOnlyHint`, enforce a per-client source allowlist, audit every call, and expose no mutation path (INV-9).

## Mission budget envelope (dry-run)

- Added `hermes_budget_set/get/check/record`.
- `budget_accounts` holds a per-mission spend envelope; `hermes_budget_check` is a read-only evaluation surface; `set`/`record` are dry-run-first and touch only the budget store.
- The D3 hard-block path (pause Mission + `budget_breaker` signal) is designed but flag-default-off and wired in a later slice.

## Deterministic placement scoring (dry-run)

- Added `hermes_placement_score/candidates/get/list`.
- Deterministic filter-and-score over the derived capability index: hard filters (enabled/reachability/identity, features, authorization ceiling, profile/workspace scope, concurrency headroom, policy) then soft scores (capability_fit, authorization_match, affinity, load_headroom, health, cost_priority), plus a `no_capable_target` escalation stub.
- Decision output only: `would_assign` is always `False`; no assignment executes. Actual dispatch stays on the existing contract/fleet/delegation authority surfaces.

## Semantic failure classification + recovery matrix

- Added `hermes_failure_classify`, `hermes_failure_taxonomy`, `hermes_recovery_matrix`, and `hermes_controller_plan_list`.
- The Ops 8-class taxonomy (§11.1) classifies an authoritative observation envelope (delegation state/verdict, runner observed_runs, worker-exit vocabulary, refined `_RESPAWN_BLOCKER_RE`, live capability negotiation) and proposes the smallest recovery action; `hermes_recovery_matrix` is the deterministic smallest-first matrix (§11.2).
- Decision output only: `would_execute` is always `False`; the sole durable write is a `controller_plan` row.

## Supervised mission controller — shadow/observe reconciler loop

- Added `hermes_controller_reconcile/status/lease_list/trigger`.
- T1–T5 trigger model; per-mission pass lease (TTL = `min(max_pass_duration, interval*2)`, heartbeat-renewed, crash-reclaimed); trigger-queue conflation; idempotency; fail-closed classification; smallest-action recovery proposal.
- A single shadow `reconcile` pass observes authoritative mission/plan/delegation/runner state, classifies it, and emits the smallest recovery action as a proposal only (`would_execute` always `False`, and the envelope carries the `would_be_commands` a higher-autonomy rung would run — D10 is out of this slice). The controller never dispatches, completes, or approves; its only durable writes are `controller_plan`, `controller_telemetry`, and the pass lease. No deploy / process mutation occurs.

## Controller telemetry and health

- Added 24h-windowed aggregated counters with truthful stale-lease-reclaim accounting via telemetry columns.
- Deterministic per-pass GREEN / YELLOW / RED tiers plus a controller rollup.
- RED spools a fleet-attention `INTERRUPT` envelope to the existing delivery-broker lane (no self-send); stale heartbeat → RED, and spool failure raises (INV-10 loudness).

## Authority boundary ladder

- The vNext authority ladder is preserved and documented: read-only surfaces remain read-only; mutating surfaces are dry-run-first; the controller is a decision-only shadow in this slice (`would_execute`/`would_assign` always false, no deploy path).
- `serverInfo.version` continues to advertise the checkout version (`versioning.VERSION`) so MCP clients can detect stale processes.

## Compatibility and safety

- Hermes GPT remains local-first and intended for trusted-machine/private-boundary deployment; default behavior is read-only and mutating Operator actions stay opt-in and dry-run-first.

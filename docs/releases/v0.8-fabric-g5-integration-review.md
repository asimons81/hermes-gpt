## Cross-slice composition strategy

G5 intentionally tests production seams rather than duplicating the G4 slice unit suites. The primary composition path is:

`execution.backend=auto` → G4-C capability-aware routing → managed Fabric dispatch → peer execution → durable coordinator reconciliation → evidence/artifact admission → existing Work Contract validation → read-only Flight Deck projection.

The G4-A/B/C/D focused suites remain in CI alongside the new G5 integration file so failure-mode coverage is preserved while the composition path is exercised end to end in-process.

## Source-of-truth audit

The G5 implementation is deliberately test/review infrastructure plus a stricter release-hygiene guard. It does not add a new Fabric runtime authority surface.

Runtime source-of-truth remains:

- managed dispatch/evidence and coordinator journal: `operator_fabric.py`;
- G4-C write ownership, execution-unit reconciliation, artifact snapshots/admission, and retry lineage: `operator_fabric_g4c.py`, `fabric_write_guard.py`, `fabric_artifacts.py`;

- Work Contract observed-state verdicts: `operator_contract.py`;
- read-only operator visibility: `operator_fabric_view.py`, `ui_fabric.py`;

Architecture source-of-truth remains the accepted v0.8 ADR/security package under `docs/design/` and `docs/releases/`; public release/operator documentation should be updated only in the release-publication gate, not by inventing pre-release behavior in current v0.7 docs.

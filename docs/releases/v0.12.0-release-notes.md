Hermes GPT v0.12.0 is the vNext slice-2 release. It gives the two mutation paths designed in earlier slices — the D3 budget hard-block and the controller's L2 rung — a real, gated execution path. Both are **DEFAULT OFF**: with their machine gates unset, every existing read-only, dry-run, and shadow surface returns byte-identical output and performs no writes, and the connector surface stays pinned at **137 tools** with no duplicate registration.

## Budget D3 hard-block enforcement (gated, default off)

- Added `operator_mission_budget.enforce_budget_breaker`, which executes the on-crossing action set atomically from the caller's perspective:
  - pause the Mission through the existing transition surface with reason `budget_breaker`;
  - emit one fleet-attention `INTERRUPT` envelope through the existing controller attention spool (`fleet-attention-envelope/v1`, `row_key="budget_breaker"`, `classification="budget_crossing"`, `proposed_action="pause_mission"`, bounded ids/enums only) — delivery stays the broker lane's job, and the server never self-sends;
  - append one `budget_events` row with `event_type="break"` carrying bounded numbers/ids/enums/hashes only.
- The full gate set must hold, evaluated fresh in a fixed order: per-call `confirm`, the `HERMES_GPT_BUDGET_HARD_BLOCK=1` machine gate, live Operator policy (enabled plus `direct` apply mode), and the per-mission `hard_block_enabled` plus `pause_on_cross` policy flags. The first missing gate returns its stable reason code with zero writes and no partial action.
- Anti-TOCTOU: the operator policy is re-snapshotted immediately before acting; a policy change aborts with `refused: policy_changed` and zero writes.
- Fail-closed and idempotent: a Mission that is not in a pausable state is marked `need_attention` with reason `not_pausable` (no dispatch, at most one spool entry); repeating enforcement for an already-broken Mission returns `already_enforced` and appends no second `break` row.
- `hermes_budget_check` gains keyword-only `enforce` / `confirm`. The default `enforce=False` result is byte-identical to the previous read-only evaluation, and the MCP tool signature is unchanged.
- The controller reconcile pass records a `budget_enforcement` outcome only when the machine gate is armed; otherwise the pass output is byte-identical and nothing is written.

## Controller L2 rung and placement-informed dispatch (gated, default off)

- Added the L2 rung to the reconcile pass. When, and only when, the per-call `confirm`, the `HERMES_GPT_CONTROLLER_EXECUTE=1` machine gate, live Operator policy (enabled, `direct` apply mode, and `workspace` level), and `dry_run=false` all hold, the pass executes **at most one** action: its single smallest computed recovery action, dispatched through the **existing** Work Contract and delegation authority surfaces. No new dispatch mechanism was introduced.
- Placement-informed target selection reuses the existing scoring filters and scores unchanged; `operator_placement.dispatch_view` derives `would_assign` truthfully — `true` only for a dispatch that actually happened.
- Idempotency and crash safety: the action is keyed by the existing proposal idempotency key, and a pre-dispatch intent row is persisted **before** the dispatch call, so a replay returns `already_executed` and a crash mid-execution reconciles fail-closed instead of re-dispatching.
- Every other combination stays decision-only and returns an additive `execution` block naming a stable refusal reason (`confirm_required`, `operator_policy_required`, `workspace_required`, `dry_run`, `no_action`, `not_executable_attention`, `unsupported_action`, `already_executed`, `no_capable_target`, `authorization_class_not_supported`, `approval_gate`, `secret_like_requirement`).
- Surfaces: `hermes_controller_reconcile` gains a `confirm` parameter (default `False`); `hermes_controller_status` reports `execution_enabled` plus an executions rollup (`executed`, `dispatched`, `failed`, `refused`, `refused_by_reason`, `placement_escalations`); executed actions are recorded on the existing `controller_plan` decision rows and the existing `controller_telemetry` ledger.
- Default-off behavior is additive only: with the machine gate unset, the pass envelope is byte-identical to the previous release (same keys, no `execution` member, `would_execute` false), `dry_run=true` remains a zero-write preview, and the only durable difference is four additive, initially-empty execution-ledger columns on `controller_telemetry`.

## Retained prohibitions

The §7.7 prohibition matrix still binds at L2, and each prohibition is covered by a test that attempts the violation and asserts refusal with zero writes. The rung cannot:

- complete a mission or plan node, or approve anything (including anything on the human approval frontier);
- weaken evidence (contract completion criteria stay unmet, expected artifacts stay empty);
- auto-redispatch `reconciling` work;
- rewrite a mission plan, and it cannot bypass Mission version CAS or delegation `authority_version`;
- retry without bound (one action per pass; a failed dispatch is terminal for that pass and is classified, never reported as silent success);
- place or dispatch without authority — `no_capable_target` escalates through the existing attention spool instead of auto-resolving, and high-impact authorization classes keep their human gate;
- read or write secrets or secret-like paths, or accept a secret-like requirement.

The enforcement path likewise never resumes a Mission, never raises a quota, and never lowers a quota to escape an overrun; resume and quota changes stay human paths.

## Compatibility and safety

- Hermes GPT remains local-first and intended for trusted-machine or private-boundary deployment. Default behavior is read-only, mutating Operator actions stay opt-in and dry-run-first, and public unauthenticated Operator hosting remains unsupported.
- Existing behavior is preserved: with the v0.12 machine gates unset, the slice-1 and earlier surfaces are byte-identical, and the connector acceptance gate pins the merged surface at **137 tools** with no duplicate registration and `serverInfo.version` = `versioning.VERSION` for the checkout.
- No new tables and no destructive migration. Enforcement adds only the `break` value on the existing `budget_events` table; the L2 rung adds only additive telemetry columns.
- Compatibility with the previous SDK matrix is unchanged: `mcp` 1.28.1+ or 2.x.
- A GitHub release and a PyPI release are separate distribution channels; verify the published version on each channel independently.

## Rollback

- Installs: pin back to `hermes-gpt==0.11.0` (PyPI) or check out tag `v0.11.0`.
- Live deployments: restore the previous checkout commit and restart the server unit. No destructive migration is involved, and both v0.12 rungs are default-off — unsetting `HERMES_GPT_BUDGET_HARD_BLOCK` and `HERMES_GPT_CONTROLLER_EXECUTE` (or returning the deployment to the previous checkout) restores the previous decision-only behavior.

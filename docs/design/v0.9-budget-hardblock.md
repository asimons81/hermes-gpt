# Mission budget envelope & hard-block path (v0.9)

**Card:** `t_78e597c6` — Phase 2: `budget_accounts` + `budget_check` envelope (dry-run).
**Proposal:** §17 item 4, D3, §6.2 `budget_accounts`, §10.6 INV-8 / INV-9.
**Module:** `operator_mission_budget.py`. **Tests:** `test_operator_mission_budget.py`.
**Status:** Implementation is **Phase 2 dry-run** (check + record only). The
hard-block *path* described here is **design only**; its enforcement is wired in
Phase 4/5 (supervised auto-dispatch / autonomy graduation). It is NOT active.

---

## 1. What this slice does

A Mission gets an optional mission-scoped **spend envelope**. The envelope is an
additive row in `budget_accounts`:

| column | meaning |
|---|---|
| `mission_id` | FK to `missions` (one envelope per Mission) |
| `quota` | the spend limit (`REAL`, > 0) |
| `spend` | accumulated spend (`REAL`, >= 0) |
| `unit` | spend unit: `tokens` \| `minutes` \| `usd` |
| `policy_json` | `hermes.budget-policy/v1` document (see §2) |
| `account_sha256` | sha256 over `{quota, policy}` (integrity / drift detection) |

`budget_events` is an append-only per-mission log of spend records
(`amount`, `spend_after`, `status`, `hard_block`, `ref`, `reason_sha256`).

Public tools (registered in `server.py`):

- `hermes_budget_set(mission_id, quota, policy_json)` — create / update the envelope.
- `hermes_budget_get(mission_id)` — read the envelope (read-only).
- `hermes_budget_check(mission_id)` — **the `budget_check` surface**: evaluate spend
  vs quota and report the would-be D3 behavior (read-only).
- `hermes_budget_record(mission_id, amount, ref, reason)` — record a spend
  increment (dry-run enforcement; never pauses the Mission).

In Phase 2, **no tool can pause a Mission or raise a real human signal.** The
record / check surfaces only compute and report.

## 2. Budget policy (`hermes.budget-policy/v1`)

```json
{
  "schema": "hermes.budget-policy/v1",
  "unit": "tokens",
  "hard_block_enabled": false,
  "pause_on_cross": true,
  "breaker_signal": "budget_breaker",
  "authorization_class": "reversible_write"
}
```

- `hard_block_enabled` — **defaults to `false`.** The hard-stop semantics are
  designed (D3) and carried here, but the *enforcement* is wired in Phase 4/5.
  Even when set to `true`, Phase 2 only reports `would_pause` and never executes it.
- `pause_on_cross` — D3 on-crossing behavior: pause Mission + raise `breaker_signal`.
- `breaker_signal` — the human-facing signal name (default `budget_breaker`).
- `authorization_class` — the action class this envelope implies
  (`read_only` / `reversible_write` / `high_impact`), used by the authority
  ceiling (`min(ceiling, contract.authorization, target.max_authorization)`).

## 3. Envelope evaluation (INV-8)

`spend < quota` → `within` (un-gated). `spend >= quota` → `crossing` (the edge).

```
env = {
  "unit", "spend", "quota", "status": "within"|"crossing"|"invalid",
  "within_envelope": spend < quota,
  "crosses_envelope": spend >= quota,
  "consumed": spend/quota, "utilization_percent", "remaining": max(0, quota-spend),
}
```

`validate_envelope(policy, spend, quota)` and `within_envelope(policy, spend, quota)`
are pure predicates exposed for tests / later controller phases. Bad envelopes
(non-positive quota, NaN/inf, negative spend) are fail-closed **not within**.
INV-8 holds: within-envelope spend is never gated; the boundary is the only gate.

## 4. Pass 2 → `budget_check` report

`hermes_budget_check` returns the envelope `status` plus a `block` object:

```json
{
  "status": "crossing",
  "crosses_envelope": true,
  "block": {
    "hard_block_enabled": false,      // from policy (default off)
    "pause_on_cross": true,
    "breaker_signal": "budget_breaker",
    "would_pause": false,              // crossing AND hard_block_enabled AND pause_on_cross
    "enforced_now": false,             // Phase 2 always dry-run w.r.t. the Mission
    "enforcement_phase": "phase_4_5"
  }
}
```

In Phase 2 `would_pause` is computed but `enforced_now` is always `false`.

## 5. Hard-block path (D3) — DESIGN, wired in Phase 4/5

### 5.1 Trigger

The controller (Phase 3/4) or a supervised dispatch step calls `budget_check`
(for a mission with `hard_block_enabled=true`) and observes
`block.would_pause == true` (i.e. `crosses_envelope`). This is the edge.

### 5.2 Decided behavior (D3 / §10.5 "spend > envelope → O + spend breaker")

On crossing, the controller **must**:

1. **Pause the Mission** — call the existing lifecycle transition
   `hermes_mission_transition(mission_id, "paused", reason="budget_breaker")`.
   Pause is a legal `running -> paused` transition in `operator_mission_runtime`
   (`MISSION_TRANSITIONS`). If the Mission is not in a pausable state, fail-closed:
   do not dispatch further work, mark `need_attention`.
2. **Raise the human `budget_breaker` signal** — emit the escalation through the
   existing fleet-attention / human-signal broker (proposal §12: every escalation
   routed through the broker as INTERRUPT only when a human gate is genuinely
   required). Never self-send from inside the loop.
3. **Record** a `budget_events` row with `event_type="break"` and the crossing
   `spend_after`.

### 5.3 Authority (INV-8 + §10.5)

- The pause is an **Owner-gated** action (`O` for spend > envelope). A distinct
  principal must approve any resume / quota raise (`reviewer ≠ actor`), so the
  controller can pause but cannot unilaterally resume past the envelope.
- The controller never **lowers** a quota or **raises** its own ceiling to
  "escape" an overrun — that is `O-ACK` only (INV-1 no self-escalation).

### 5.4 Why a flag, default off

The spin-up is explicitly shadow-first: real enforcement must not fire until the
QA evidence model (Stage A/B) **and** the Security authority model are present
(D10) **and** a real shadow/dry-run has run without unexpected mutation. So
`hard_block_enabled` defaults `false`; Phase 2 ships the semantics and the report,
Phase 4/5 ships the enforcement under `direct` + confirm + the authority ceiling.

### 5.5 Fail-closed invariants carried into Phase 4/5

- INV-2 fail-closed completion: an over-envelope mission is never completed.
- INV-1 no self-escalation: the controller cannot raise its ceiling or lower quota.
- INV-8 spend envelope: within-envelope spend un-gated; boundary is the gate.
- INV-9 data containment: `budget_accounts` / `budget_events` store bounded
  numbers, refs and hashes only (`reason` stored as `reason_sha256`; `ref`
  validated against the ref alphabet; secret-like policy rejected by `redact_output`).
- INV-11 linearized authority: re-snapshot the Operator policy before any
  Phase 4/5 pause/signal action (anti-TOCTOU).

## 6. Not in this slice (explicit non-goals)

- No dispatch of a pause, no `hermes_mission_transition`, no human signal is
  emitted by Phase 2.
- No quota auto-escalation, no auto-resume, no refund/clawback surface.
- No change to recurring schedules, fleet topology, gateway ownership, provider
  architecture, credentials, or authority manifest.
- No persistence of raw prompts / transcripts / secrets; INV-9 holds strictly.

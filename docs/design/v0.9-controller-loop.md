# v0.9 — Supervised mission controller (shadow/observe reconciler loop)

Implements architecture proposal §17 item 6 / §7 / D2 / D10 in the hermes-gpt
sidecar (kanban t_ad1e6d07). **Shadow/observe mode only** — the controller
observes, classifies, and emits the smallest recovery action as decision output;
it mutates nothing outside its own surfaces, dispatches nothing, completes
nothing, and approves nothing (§7.7 hard walls, D5/P3).

## Scope

- **D2 controller form factor.** A long-running controller *process* in the
  hermes-gpt sidecar that drives the existing host Kanban dispatcher +
  ProviderProfile routing via `import_hermes` / `seams.py` protocols (host
  `kanban_watchers` left running as-is). This slice ships the loop body and the
  single-pass engine; it does **not** start the process (no deploy / no process
  mutation).
- **L0/L1 only.** `operator_controller.py` runs one shadow pass per call:
  `dry_run=True` (default) is a non-persisting preview requiring only
  `read_only`; `dry_run=False` persists the L1 shadow record
  (`controller_plan`/`controller_telemetry`/pass lease/heartbeat) and
  requires `workspace` + direct apply mode. No L2+ mutation path exists;
  `would_execute` is hard constant `False`.

## Surfaces

- `hermes_controller_reconcile` — run one shadow pass over a mission
  (observe → classify → smallest action; decision output only).
- `hermes_controller_status` — read-only aggregate health (§12.2).
- `hermes_controller_lease_list` — current per-mission pass leases + trigger
  queue conflation state (read-only).
- `hermes_controller_trigger` — enqueue a T1–T5 work request (advisory).

## Loop (§7.1–§7.6)

Trigger model **T1 period** / **T2 live-event** / **T3 dependency** / **T4 health**
/ **T5 manual** enqueues a work request. The controller:

1. **Conflates** (§7.1) — one in-flight pass per mission; a second trigger while a
   pass holds the lease sets `recheck_needed` (`controller_pass_lease`).
2. **Acquires the per-mission pass lease** (§7.3) — a single guarded `UPDATE` on
   `(lease_expires IS NULL OR lease_expires < now)`; TTL =
   `min(max_pass_duration, interval*2)` (default 90s interval → 180s TTL);
   heartbeat-renewed; crash-reclaimed by TTL expiry (kill -9 of the owning
   process reclaims on the next trigger). CAS on `lease_lock` prevents a live pass
   being stolen.
3. **Classifies** (§11.1) via `operator_failure_semantics` over an authoritative
   observation envelope (mission/plan/delegation/runner). The trigger is not the
   decision. Un-observable state fail-closes to `unknown` → `blocked` +
   `need_attention` (§7.5).
4. **Applies the smallest action** from the recovery matrix (§11.2) as decision
   output only.
5. **Idempotency** (§7.4) — `sha256(mission_id|node|stage_id|contract_sha|attempt_seq)`.
6. **Replan** (§7.6) — proposal only for `semantic_failure`, bounded (≤1),
   routed through the existing decompose/advance tools, never executed here.
   Hard walls (authority/capability/policy) never replan — they escalate.

## Durability & zero side effects

The controller's only durable writes are its own surfaces (§6.2 / §12.2):

- `controller_plan` — the recorded decision (shared table, `operator_failure_semantics`).
- `controller_pass_lease` — per-mission concurrency safety.
- `controller_telemetry` — per-pass telemetry.
- `controller_trigger_queue` — conflated trigger work requests.
- `missions/controller_heartbeat.json` — watchdog liveness file.

It never touches `missions` / `mission_events` / `mission_plans` / `plan_nodes` /
`attachments` or the `delegations` store (verified by a store diff in
`test_operator_controller` and the live smoke).

## Authority gating (D10)

Mutating autonomy is gated on BOTH the QA evidence model and the Security
authority model being present — both parents are `done` for this card
(t_4bdc1fa3 authority boundary, t_b4b4cc42 evidence gate). This slice stays at
L0/L1. The controller cannot complete/approve/weaken evidence/auto-redispatch
`reconciling`/rewrite a plan/create an infinite retry/place without authority/
bypass Mission version CAS or delegation `authority_version`/touch secrets
(§7.7).

## INV-9 data containment

No raw prompt, transcript, error body, objective, credential, or secret-path
content is persisted — only bounded enums, hashes, matched token ids, counts,
and refs.

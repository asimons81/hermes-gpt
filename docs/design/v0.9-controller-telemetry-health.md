# v0.9 Controller Telemetry, Health Surface, and GREEN/YELLOW/RED Routing

Status: current (kanban `t_e8468723`, proposal §17 item 8 + §12.2). Extends the
supervised mission controller (`v0.9-controller-loop.md`, `t_ad1e6d07`) with
the observability and alerting layer. Decision output only — `would_execute`
remains hard False everywhere; this card adds no mutating autonomy.

## Scope

- Completes §12.2 aggregate health on `controller_status()`.
- Adds deterministic per-pass GREEN/YELLOW/RED tiers and a controller-level
  tier rollup.
- RED passes spool a fleet-attention INTERRUPT envelope for the existing
  delivery-broker lane. The controller NEVER sends (no self-send from inside
  the loop); transport stays with the ops fleet-attention broker.
- INV-10 (auditability): a refused gate is as loud as permitted — stale
  heartbeat reads RED, spool failure raises, tier + spool counts surface in
  the status tool and its audit record.

## Telemetry (per pass)

Parent card's `controller_telemetry` rows gain two columns (additive
`ALTER TABLE ... ADD COLUMN`, presence-guarded, in-place migration):

- `lease_reclaimed` — true when the pass acquired a lease by reclaiming an
  expired one (crash reclaim). Distinct from conflation (`pass_result=stale`
  on a held live lease), which is normal loop behavior and NOT a reclaim.
- `escalation_tier` — GREEN | YELLOW | RED for the pass (§12.2 alerting).

Per-pass §12.2 fields remain as the parent card built them: `trigger_kind`,
`duration_ms`, `pass_result` (noop/dispatched/recovered/escalated/blocked/
stale), `actions_taken`, `classification`, `lease_acquired` (+ now
`lease_reclaimed`, `escalation_tier`).

## Aggregate health (`controller_status()`)

All counters are windowed to the last 24 h (`AGGREGATE_WINDOW_SECONDS`);
`pass_results_all_time` keeps unwindowed totals for forensics.

- `controller_live` — heartbeat file fresh (`HEARTBEAT_STALE_SECONDS` = 180 s).
- `last_pass_age_s`, `last_beat` — heartbeat age/ISO timestamp.
- `missions_reconciled_24h` — distinct missions with a pass in the window.
- `passes_24h` — total passes in the window.
- `active_passes` — rows currently in `controller_pass_lease`.
- `recoveries` — `pass_result=recovered` in-window.
- `escalations` — `escalated + blocked` in-window.
- `retry_storms_prevented` — `blocked` in-window (parked walls are storms not
  retried).
- `stale_lease_reclaims` — `lease_reclaimed=1` in-window (true reclaims).
- `classification_uncertainty` — `classification=unknown` in-window.
- `per_class` — per-classification counters (windowed).
- `per_tier` — GREEN/YELLOW/RED counters (windowed).
- `attention_spooled` — envelopes awaiting broker flush.
- `tier` + `tier_reasons` — controller-level rollup (below).

## Tier derivation (deterministic, §12.2)

Per pass (`derive_pass_tier`), first match wins:

1. RED — hard-wall row keys: `park_authority`, `park_capability`,
   `breaker_exhausted`, `unknown_fail_closed`, `fail_closed_evidence`
   (a human gate is genuinely required; INV-10 keeps these loud).
2. RED — mission `blocked` with `need_attention` stuck longer than
   `STALE_RECONCILING_SECONDS` (3600 s) — "blocked/reconciling > stale
   threshold" per §12.2.
3. RED — `classification=unknown` without a hard-wall row (fail-closed
   unknown is never quiet).
4. YELLOW — classes `transient`, `semantic_failure`, `environment`,
   `ambiguous` (self-healing or routable through normal lanes; count-only).
5. GREEN — steady states: `none*`, `waiting`, `cancelled`.
6. YELLOW — anything unmapped (fail-open to count-only, never silent GREEN).

Controller-level rollup (`tier` in status): RED if the heartbeat is stale
(unobservable controller = fail-closed RED) or any RED pass in-window;
else YELLOW if any YELLOW pass in-window; else GREEN.

## RED routing — attention spool (no self-send)

A RED pass appends one fleet-attention envelope/v1 JSON line to
`missions/controller_attention_spool.jsonl`:

- `attention_class=INTERRUPT`, `severity=P1`, `state=open`,
  `action_required=true`, `approval_required` only for `park_authority`.
- `source`: `system` / `ops` / job `hermes-gpt-controller`.
- `dedupe_key=controller:red:<mission_id>:<row_key>` — stable across passes
  for the same wall; the router/broker dedupe layers suppress repeats.
- INV-9: only ids, bounded enums, fixed matrix strings; never raw
  objective/error/secret text (test + smoke assert the blob).
- `metadata` carries `tier`, `mode`, `would_execute=false`, classification,
  row_key, bounded uncertainty + escalation reasons.

The controller never delivers. The existing ops lane
(fleet-attention observer → router classify → active delivery broker) owns
transport; a bridge from spool → canonical inbox is deliberately NOT in this
slice (that would couple the loop to the delivery plane; flag to the
orchestrator if/when cutover is wanted).

Dry-mode proof (live smoke `.qa-tmp/smoke_controller_health.py`): the spooled
envelope passes the REAL router CLI (`validate` clean, `classify` →
`would_interrupt`/INTERRUPT), is emitted into an ISOLATED sandbox ledger, and
the REAL broker (`bootstrap` + `process_realtime`, stub sender, sandbox
cutover policy) produces exactly one INTERRUPT receipt — zero Telegram, zero
canonical-ledger writes.

## Surfaces

No new MCP tools (slice AC-10 smallest surface; the shared server.py
hotspot is untouched — connector count stays 137). The existing
`hermes_controller_status` now serves the richer aggregate + `tier` +
`per_tier` + `attention_spooled`, and its audit record carries tier +
spooled count. `hermes_controller_lease_list` / `_reconcile` / `_trigger`
are unchanged from the parent card.

## INV-10 (refused gate as loud as permitted)

- Stale/missing heartbeat → status `tier=RED`, reason
  `heartbeat_stale_or_missing`.
- Spool write failure raises out of the pass (never silently drops a
  human-gate signal).
- Loop-tick pass errors carry `escalation_tier=RED` in-band.
- Status tool audit records tier + attention_spooled.

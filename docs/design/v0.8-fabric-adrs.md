# Hermes GPT v0.8 Fabric ADR Set

- Status: PROPOSED, G2
- Program: #27
- Gate: #29
- Research source: `docs/releases/v0.8-fabric-research-package.md`

No ADR in this document authorizes implementation until G2 and G3 gates pass.

## ADR-009: Use official Hermes A2A v1.0 as Fabric transport

**Status:** Proposed

**Decision:** Do not create a second network protocol. Use configured/authenticated Hermes A2A peers for discovery, submit, poll, cancel, subscribe/push where useful, and bounded transport.

**Rationale:** Current Hermes GPT fleet and upstream Hermes already implement the required transport primitives. Fabric's missing value is deterministic authority, durability, placement, evidence, and recovery semantics.

**Constraint:** A2A transport success is not completion proof.

## ADR-010: Require a managed deterministic Fabric peer for verified remote stages

**Status:** Proposed

**Decision:** Generic A2A compatibility is insufficient for a stage to count as verified Fabric execution. A managed peer must expose a compatible Hermes GPT Fabric acceptance/execution boundary.

**Rationale:** Current generic inbound A2A work is injected into the live agent session. Natural-language interpretation cannot be the enforcement point for write-capable authority envelopes.

**Compatibility:** Ordinary A2A delegation to third-party agents remains supported outside verified Fabric semantics.

## ADR-011: Version the distributed seam instead of silently redefining v0.7

**Status:** Proposed

**Decision:** Introduce additive Fabric dispatch/evidence interfaces with explicit lifecycle semantics rather than changing the meaning of the tiny v0.7 `DispatchAdapter`/`EvidenceProvider` protocols in place.

**Required operations:** availability/capabilities, dispatch, poll, recover, collect evidence, cancel, reconcile.

## ADR-012: Persist coordinator dispatch and attempt lineage

**Status:** Proposed

**Decision:** Create a durable coordinator journal keyed by stable `dispatch_id` and per-run `attempt_id`.

**Must bind:** workflow/stage/task, contract hash, peer/backend, capability snapshot, authority/scope, remote task ID, state, timestamps, recovery/cancel lineage.

**Rationale:** RPC and remote task state alone cannot safely recover distributed mutation after restart.

## ADR-013: Persist peer Fabric attempt state before write-capable execution

**Status:** Proposed

**Decision:** A managed peer durably records accepted attempt identity/state before it begins write-capable mutation.

**Rationale:** Current pinned upstream A2A `TaskStore` is in-memory and may disappear on peer restart.

## ADR-014: Separate stable dispatch identity from retry attempt identity

**Status:** Proposed

**Decision:** One logical stage dispatch keeps a stable `dispatch_id`; every actual execution attempt has a unique `attempt_id`.

**Replay rule:** identical replay of the same dispatch/attempt returns existing state; conflicting reuse is rejected.

## ADR-015: Keep peer enrollment and authority server-controlled

**Status:** Proposed

**Decision:** Fabric API callers reference stable peer names only. URL, credential, expected identity, allowed profiles, authorization ceiling, and public/high-impact posture come from server-owned configuration/registry.

**Open detail:** versioned successor/evolution of the current narrow fleet authority manifest.

## ADR-016: Classify capability provenance and freshness

**Status:** Proposed

**Decision:** Capability data is not a single trusted blob. Fields are classified as coordinator-observed, peer-attested, coordinator-derived, or soft hints.

**Rule:** stale or unknown positive requirements cannot make a peer eligible.

## ADR-017: Route with hard filters before soft scoring

**Status:** Proposed

**Decision:** Automatic placement first excludes unsafe/incompatible candidates, then deterministically ranks only eligible targets.

**Hard filters:** identity, authority, profile, protocol, freshness, health, runner/model/provider/tool/hardware, workspace, confinement, artifact transfer, concurrency, forbidden/public/high-impact policy.

**Soft signals:** locality, load, latency, hardware fit, optional grounded cost.

**Constraint:** upstream conversational `a2a_orchestrate(..., best)` is not Fabric scheduler policy.

## ADR-018: Preserve explicit placement without creating a bypass

**Status:** Proposed

**Decision:** Explicit peer/backend selection remains supported but still passes all hard eligibility and authority checks.

## ADR-019: Use logical remote workspace mapping

**Status:** Proposed

**Decision:** Contracts/Fabric requests identify approved logical workspace/project scope. Peer-local absolute paths are resolved from server-owned mapping.

**Constraint:** callers cannot supply arbitrary remote absolute paths.

## ADR-020: Define versioned Fabric evidence and preserve coordinator verdict ownership

**Status:** Proposed

**Decision:** Managed peers return `hermes.fabric-evidence/v1` observations and artifact manifests. The coordinator admits them as evidence inputs and runs the existing Work Contract validation semantics.

**Constraint:** remote `SATISFIED` is never authoritative.

## ADR-021: Reuse export-style controls for remote artifacts

**Status:** Proposed

**Decision:** Artifact admission requires logical name, bounded size, digest, media type where useful, producer lineage, approved transfer binding, and secret/path protections.

**Constraint:** remote absolute paths and arbitrary external fetch URLs are not client-facing artifact authority.

## ADR-022: Make cancel attempt-specific, idempotent, and reconcileable

**Status:** Proposed

**Decision:** A2A `CancelTask` is transport, but Fabric cancellation is bound to the durable attempt and reconciled with peer runner/journal state.

## ADR-023: Prevent concurrent uncertain write attempts

**Status:** Proposed

**Decision:** An unresolved write-capable attempt prevents automatic replacement against the same bounded scope until the previous attempt is proven terminal/cancelled under the chosen mechanism.

**Open mechanism:** lease/epoch or equivalent durable ownership model.

## ADR-024: Treat restart/transport ambiguity as blocked, never successful

**Status:** Proposed

**Decision:** Coordinator restart, peer restart, missing task state, lost push/SSE, and ambiguous cancellation never auto-advance a stage or produce a satisfied contract.

**Rationale:** preserves existing `operator_recovery.py` fail-closed behavior.

## ADR-025: Polling plus durable journals define correctness

**Status:** Proposed

**Decision:** A2A streaming, subscriptions, and push may improve liveness/UX, but loss of those channels must fall back to bounded polling plus durable state without changing correctness.

## ADR-026: Extend Event History and Flight Deck through bounded read models

**Status:** Proposed

**Decision:** Add coordinator-side Fabric events and node/placement/evidence read models. Keep UI mutations on existing gated `hermes_*` action paths.

**Non-decision:** no generic WebSocket control-plane redesign in v0.8.

## ADR-027: Preserve local-only backward compatibility

**Status:** Proposed

**Decision:** Existing Work Contracts, Swarms, explicit runners, Operator/Owner gates, secret-path policy, and final human approval remain valid. Fabric auto-placement is additive.

## ADR-028: State the compromised-peer threat boundary explicitly

**Status:** Proposed

**Decision:** Fabric protects against malformed input, policy drift, accidental duplication, stale routing, buggy/overclaiming agents, and restart ambiguity. It does not claim cryptographic truth about a fully compromised remote OS that controls its own runtime credentials.

**G3 requirement:** adversarial review must judge the implementation against this explicit threat model rather than an impossible remote-attestation promise.

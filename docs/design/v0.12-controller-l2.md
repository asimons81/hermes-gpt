# Controller L2 Rung + Placement-Informed Dispatch (v0.12 slice-2, Phase 4/5)

**Card:** B1 design (feat/v012-slice2). **Implementation owner:** Pack B (`pack/v012-controller`).
**Lineage:** architecture proposal §17 item 6 / §7 / D2 / D10; `docs/design/v0.9-controller-loop.md` ("this slice stays at L0/L1"; "**No L2+ mutation path exists**"); `docs/design/v0.9-placement-scoring.md` (dry-run scoring, `would_assign=False`, `no_capable_target` escalate stub). This document is the slice-2 implementation contract for the L2 rung: the controller may EXECUTE its smallest recovery action under full gates — and nothing more.

- `reconcile_pass(...)` runs ONE shadow pass: classifies authoritative state, builds proposals via `_would_be_commands` (idempotency-keyed), writes `controller_plan` + `controller_telemetry` + pass lease; envelope reports `would_execute: False` at every emission site (1220/1321/1354 region); `_audit` carries `apply_mode` from live policy.

- `operator_placement.py`: `hermes_placement_score` / `hermes_placement_candidates` are dry-run; `would_assign: False`; empty candidate set → classification `no_capable_target` with an explicit escalate-to-Orchestrator stub ("never auto-resolve").
- D10 prerequisite models (QA evidence model + Security authority model) are PRESENT (done cards t_4bdc1fa3 authority boundary / t_b4b4cc42 evidence gate); the L2 gate below is additive on top.
- `operator_failure_semantics.py`: `would_execute` always False, sole durable write `controller_plan`.

## 2. L2 execution contract (what to build)

### 2.1 Gates (ALL required; default OFF; first failure = refusal with stable reason, zero writes)

1. `confirm=True` on the reconcile invocation (per-call).
2. `HERMES_GPT_CONTROLLER_EXECUTE=1` (global machine gate; default off).
3. Operator enabled + `apply_mode == "direct"` (live policy; re-read, not cached).
4. `workspace` bound (pass requires it, as today for persistence).
5. `dry_run=False` on the invocation (`dry_run=True` stays a truthful zero-write preview regardless of other gates).

### 2.2 Execution semantics

- When all gates pass, the pass executes AT MOST ONE action per pass: the **smallest action** from the computed `would_be_commands` list (existing smallest-first ordering; do not re-rank beyond the existing matrix).
- Supported execution targets in this slice (behavior per action kind):
  - `dispatch_ready_child` (and equivalent dispatch-style proposals): validate the target via placement scoring (see §3) and dispatch through the EXISTING authority surfaces (work contract / fleet / delegation paths already used by Operator-mode dispatch). No new dispatch mechanism.
  - Attention/park-style proposals (`park_authority`, escalations, anything whose semantic is "needs a human"): NOT executable; behave exactly as today (spool + `would_execute: False`).
  - Any unknown/new action kind: refuse (`refused: unsupported_action`) — fail closed, never guess.
- Idempotency: the executed action is keyed by the existing proposal idempotency key; before executing, check `controller_plan`/`controller_telemetry` for a prior execution of that key; a replayed/reconcile-again pass MUST NOT re-execute (`refused: already_executed`). Conflation/lease semantics unchanged.
- Atomicity: persist the pre-execution intent (plan row) BEFORE the dispatch call so a crash mid-execution is detectable and reconciled fail-closed (no duplicate dispatch on recovery).
- Envelope: unchanged shape at L0/L1. At L2 the pass envelope carries, additively:
  - `execution: {enabled: true, executed: bool, action_kind, idempotency_key, result: "dispatched"|"refused"|"failed", refused_reason: null|code, placement: {...guarded summary...}}`
  - `would_execute`: `True` exactly when an action was EXECUTED this pass (truthful); `False` otherwise. L0/L1 output remains byte-identical when `HERMES_GPT_CONTROLLER_EXECUTE` is unset.

### 2.3 Retained prohibitions (§7.7 matrix — all still bind at L2)

The controller at L2 cannot: complete a mission/node, approve anything, weaken evidence, auto-redispatch `reconciling` work, rewrite a plan, create an infinite retry, place without authority, bypass Mission version CAS, bypass delegation `authority_version`, or touch secrets/secret paths. Each prohibition must be enforced by the existing refusal paths where present, plus explicit guards where the new execution path could reach them; each needs a test that attempts the violation and asserts refusal with zero writes.

## 3. Placement-informed dispatch (Pack B second half)

- The L2 dispatch decision consults `hermes_placement_score` for the proposal's requirement: hard filters + scores as already implemented (no scoring changes) — the score output's top candidate becomes the dispatch target.
- If classification is `no_capable_target`: escalate (spool INTERRUPT via the existing helper; `escalate`-stub semantics) and do NOT dispatch; `would_assign` stays false in the placement envelope for this case.
- Placement envelope semantics at L2: `would_assign` becomes `True` ONLY when an assignment was actually dispatched under the full gate set; otherwise unchanged (`False`). Record the assignment linkage (mission_id -> target -> idempotency_key) on the existing telemetry surfaces (bounded fields only).
- No changes to the scoring math, filters, or the `no_capable_target` classification logic.

## 4. Telemetry + audit

- Executed actions are recorded on the EXISTING controller telemetry/status surfaces (new bounded counters: executed, refused-by-reason, placement-escalations) with INV-9-bounded fields only. Tier logic (GREEN/YELLOW/RED) and the RED->INTERRUPT spool path are unchanged; an execution failure must surface as the pass's classified state (fail closed), never as silent success.
- Audit records carry `apply_mode` as today; add `execution_enabled` marker. No raw objective/error/secret text anywhere.

## 5. Failure modes (must be tested)

| Condition | Required behavior |
|---|---|
| Any gate missing | refusal + zero writes + L0/L1-identical output |
| `dry_run=True` | zero-write preview even with all gates set |
| unsupported action kind | `refused: unsupported_action` |
| replay / already executed | `refused: already_executed`; no duplicate dispatch |
| crash between plan-write and dispatch | recovery reconciles fail-closed; no duplicate |
| dispatch target fails | execution failure classified; no retry loop (bounded rework only) |
| no_capable_target | escalate-only; never auto-resolve |
| spool failure on escalate | raise (loud) |

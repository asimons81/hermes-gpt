01 · DECK OVERVIEW

System status, active long-running tasks, recent event tail, and least-privilege authority posture in one read-only surface. All data comes from mission_* / events_* / contract / swarm surfaces.

02 · LAUNCH FLOW

Define → validate → dry-run → confirm → dispatch. The only mutation point is the explicit confirm at the gated hermes_* tool. Failure branches never mutate.

03 · TASK MONITOR

Stage ladder for a long-running swarm workflow, production evidence panel, gated actions (dry-run first, confirm required), and related events for the subject.

04 · EVENT HISTORY

Unified, redacted timeline from the hermes_events_* read-model. Filters, retention window, allowlist, and explicit redaction markers — no raw bodies ever rendered.

05 · EVIDENCE REVIEW

Owner-gated review acceptance: inspect observed evidence, run hermes_review_accept dry-run, confirm, then re-validate the contract to SATISFIED. Distinct reviewer enforced.

06 · AUTHORITY PANEL

Explainable least-privilege authority: current level, apply mode, level ladder, per-surface gates, allowlist semantics, and the presentation-only UI boundary.

# Flight Deck UI Presentation Contract (v0.7, D2-A)

- Status: current (v0.7.0, Flight Deck)
- Owner: hermes-dev
- Companion: `docs/design/v0.7-flight-deck-interaction-design.md` (media),
  `docs/design/v0.7-flight-deck-architecture.md` §9.2

This contract defines what a Flight Deck UI may render. Per ADR-002 the
Flight Deck is a **read-only presentation layer** over the existing MCP
surface. No new authority is introduced; the MCP surface is the UI. Any
dashboard built later is a thin consumer of the same view models.

## Data sources (read-only)

A Flight Deck consumer may render only what these surfaces return:

| Surface | Tool(s) | Authority |
|---|---|---|
| Mission Control bounded JSON | `hermes_mission_*` (12 surfaces) | read_only + allowlist |
| Event timeline | `hermes_events_query`, `hermes_events_tail` | read_only + allowlist |
| Contract status | `hermes_contract_status`, `hermes_contract_validate` | read_only (validate runs tests only when gated) |
| Swarm status | `hermes_swarm_workflow_list`, `hermes_swarm_workflow_status` | read_only |
| Review evidence | review-accept writer result surfaces | owner-gated write; read via validator |
| OAuth store | `hermes_oauth_status` | read_only; presence/expiry only |
| Authority | `hermes_operator_policy`, `hermes_operator_status` | read_only |

## No new authority

- The UI has **no mutation buttons that bypass `hermes_*` tools**. Every
  action the UI offers must call the existing gated tool (dry-run-first,
  confirm where required).
- The Flight Deck adds no new tools, no new authority classes, no parallel
  bypass of Owner Mode or secret-path protections.

## Redaction

- The UI renders only what the surfaces return; it never reads stores
  directly.
- Redaction invariants are enforced in the surfaces: no raw messages, memory
  bodies, transcripts, request dumps, credentials, or profile-secret bodies.
  `[REDACTED]` markers in sparse views are intentional (media F3).
- Event refs never point into `secrets/` or other denied paths.

## Allowlist semantics

- `HERMES_GPT_MISSION_ALLOWED_SURFACES`: unset = all read-only Mission
  surfaces; list = only listed; empty = none.
- `HERMES_GPT_EVENTS_ALLOWED_SOURCES`: unset = all read-only event sources;
  list = only listed; empty = none.
- Do not describe the unset state as "deny by default".

## Actions map to existing tools

| UI intent | Tool call |
|---|---|
| Launch long-running task | `hermes_swarm_workflow_create` → `hermes_swarm_stage_dispatch` |
| Monitor task | `hermes_swarm_workflow_status` + `hermes_events_query` |
| Advance a stage | `hermes_swarm_stage_advance` (dry-run first, confirm) |
| Record review evidence | `hermes_review_accept` (owner + confirm) |
| Reconcile after restart | `hermes_swarm_reconcile` (dry-run default, apply gate) |
| Revoke OAuth tokens | `hermes_oauth_revoke` (owner + confirm; pending legal) |

## Scope guardrails

- No server-rendered dashboard ships in v0.7 by default (D2-A).
- Media conflicts F1–F7 from the interaction design card are resolved here:
  read-only by construction, no UI-only mutation, visible redaction,
  dry-run before confirm, evidence over assertion, fail-closed visibility,
  authority transparency, bounded everything.

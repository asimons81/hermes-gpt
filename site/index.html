v0.10.0 vNext • Local-first • Supervised mission autonomy

Hermes Agent now has a supervised mission controller.

Hermes GPT v0.10.0 ships vNext slice 1: deterministic MissionPlan decomposition, read-only capability-manifest and mission-ledger views, a dry-run budget envelope, placement scoring, semantic failure classification, and a shadow/observe controller. The slice is strictly additive and decision-only — none of the 27 new tools can mutate a Mission, dispatch work, or approve anything.

vNext slice 1

Decision-only autonomy. Nothing ships without you.

Every new surface preserves the read-only / dry-run / shadow authority ladder. Derived views inform; the controller proposes; existing authority surfaces decide.

01

MissionPlan Decomposition

hermes_plan_create/get/list/validate/decompose/review/node_transition/set_status: a deterministic, bounded decomposition DAG over a MissionSpec. Plan mutations touch only the isolated plan store and are read-only with respect to the Mission lifecycle.

02

Capability Manifest + Mission Ledger

hermes_capability_manifest folds the Fabric node registry, Fleet authority manifest, profile toolsets/skills, and provider manifests into one queryable index. hermes_mission_ledger is a merged, replayable, cursor-paginated event timeline. No mutation path exists.

03

Budget Envelope (dry-run)

hermes_budget_set/get/check/record: a per-mission spend envelope with a read-only budget_check evaluation surface. The hard-block path is designed but flag-default-off in this slice.

04

Placement Scoring (dry-run)

hermes_placement_score/candidates/get/list: deterministic hard filters then soft scores over the derived capability index. Decision output only — would_assign is always False; actual dispatch stays on the existing contract, fleet, and delegation authority surfaces.

05

Failure Semantics + Recovery Matrix

An 8-class taxonomy classifies an authoritative observation envelope and proposes the deterministic smallest-first recovery action. would_execute is always False; the sole durable write is a controller_plan row.

06

Shadow Controller + Telemetry

hermes_controller_reconcile/status/lease_list/trigger: a T1–T5 trigger model, per-mission pass leases (TTL, heartbeat-renewed, crash-reclaimed), and a single shadow reconcile pass that emits proposals only. Telemetry tiers GREEN / YELLOW / RED; RED spools a fleet-attention interrupt to the delivery-broker lane.

System Architecture

Observe, classify, propose. Humans decide.

The controller watches authoritative state through derived views and proposes the smallest recovery action. It never dispatches, completes, or approves.

01Client Request

ChatGPT, Codex, Cursor, Claude Desktop, or another trusted MCP client submits a bounded request to Hermes GPT.

02Observe

The controller observes authoritative mission, plan, delegation, and runner state through the derived capability manifest and mission ledger.

03Classify + Propose

The 8-class failure taxonomy classifies observed state and the recovery matrix emits the smallest recovery action as a proposal — would_execute always false.

04Human Decision

Dispatch, completion, and approval remain on the existing authority surfaces: Work Contracts, Fabric, delegations, and Owner-gated final approval.

Capabilities

Local-first control plane, now supervised.

vNext adds the controller layer without weakening the security and evidence invariants shipped in v0.6 through v0.9.

01

Operator and Owner Policy

Tiered authority from read_only through owner, with explicit direct mode, confirmation gates, and dry-run-first mutation.

02

Work Contracts

Completion is validated from observed state. Missing required evidence cannot become SATISFIED.

03

Missions, Delegations + Live Events

v0.9 adds the first-class durable Mission runtime with Owner-gated final approval, unified delegation lineage, a durable event bus with a WebSocket stream, and runner-neutral job supervision.

04

Fabric Cross-Machine Execution

v0.8 Fabric: authenticated peers, capability-aware auto routing, hash-verified remote evidence and artifacts, and same-attempt reconciliation — with the coordinator authoritative.

05

OpenAI Secure MCP Tunnel + Bounded Export

Supported OpenAI products reach loopback Hermes GPT through an outbound-only private tunnel path, and hermes_export_file provides workspace-authorized binary transfer with denied-path enforcement and size caps.

06

Flight Deck + Connector Gate

Mission Control, event history, review evidence, diagnostics, recovery tools, and Fabric routing views keep long-running autonomy inspectable. The connector acceptance gate pins the merged v0.10.0 surface at 137 tools with no duplicate registration.

Install

Get Hermes GPT running.

Install from PyPI or run the current checkout. Keep the HTTP server on loopback unless you deliberately configure an authenticated private boundary.

Install package
python -m pip install hermes-gpt

Check the PyPI badge in the repository README before relying on version-specific features.

Run current source
git clone https://github.com/asimons81/hermes-gpt.git
cd hermes-gpt
python -m pip install .
hermes-gpt
Loopback Streamable HTTP
python server.py --http --host 127.0.0.1 --port 7677

Endpoint: http://127.0.0.1:7677/mcp. For supported OpenAI products, prefer the OpenAI Secure MCP Tunnel path documented in the repository.
